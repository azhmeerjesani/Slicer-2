# Lesion Network Mapping: statistics

This page describes what the statistics of the [Lesion Network Mapping](lesionnetworkmapping.md) module compute, with
which defaults, and what it deliberately does not offer. Every number on this page is a default of the code as built;
the cards of the Map workspace show the values that were actually used, and the sidecars and the methods text record
them. Where a method is a proposal or comes from a single preprint, the module says so in the output.

:::{note}

**Research use only.** Lesion network mapping specificity is debated (see the
[disclaimer](lesionnetworkmapping.md#research-use-only)). No test, null or similarity measure on this page produces a
"specific" verdict, and none of the outputs is wording for a clinical decision. The module writes "network associated
with …", never "localizes" or "causal circuit".

:::

## Which statistic is used where

- **Per-lesion maps** are written unthresholded: the mean r (`AvgR`), the mean Fisher z (`AvgRFz`) and the one-sample T
  of the subject-wise Fz values (`T`).
- **Group statistics** (the general linear model, symptom mapping, validation and the nulls) take the **mean Fz** by
  default, because it does not depend on the number of connectome subjects. T can be chosen as the input. The choice is
  recorded in `design.json` and in the methods text.
- **An effect size accompanies every p map:** Hedges g for group contrasts, the partial r for scores, the partial eta²
  for an F test, and the mean Fz for single maps. Validation reports AUC, odds ratio, r and out-of-sample R² with
  confidence intervals.

## Thresholds per N

A threshold is a **rule**, not a number. It is resolved again from the rule, the number of subjects N and the number of
voxels V each time a map is displayed or exported (`thresholds.resolve`), so a threshold that was derived for one N is
never reused silently for another. The derived line under the threshold shows the result, for example
"⇒ |T| ≥ 5.27 at N=1000 (df=999), V=292,019 · p_unc ≤ 1.7e-7".

| Rule | Meaning | Notes |
| ---- | ------- | ----- |
| **FWE (Bonferroni)**, the default | \|T\| at which p < α/V, two-sided, α = 0.05: `t.isf(α / 2 / V, N - 1)` | The table below |
| **\|T\| ≥ 7** (the convention) | T = 7 | Defined for about N = 1000 and **disabled for N below 900** unless you choose "Use anyway" (the override is recorded). A banner appears when N differs from the reference N by more than 10% |
| **Fz ≥ x** | an effect size on the mean Fz | Does not depend on N; the statistic switches to Fz |
| **Custom T** | a value you type | A banner appears when the map's N differs from the N it was chosen for. A map whose N is unknown can only take this rule and the two N-free rules, and shows no p value |
| **Top x %** | the value above which the top x % of in-mask voxels of this map lie (default 10) | Does not depend on N; there are no p values. This is the only kind of rule that the fast (parcel) mode accepts |

The Fz and top-percent rules are **alternatives** to the T rules, never "equivalents": T is the mean Fz divided by
(sd / √N) and the sd differs between voxels, so no Fz value corresponds to a given T and the module never converts one
into the other.

The FWE threshold per N for two mask sizes (generated by a script that calls `thresholds.resolve`). V = 292,019 is the
mask size of the GSP1000 connectome that the module's reference numbers use, and V = 228,483 is the size that the
timing measurements of the Calibrate and QA cards were made at:

| N | FWE \|T\|, V = 292,019 | FWE \|T\|, V = 228,483 | \|T\| ≥ 7 convention | Notes |
| - | - | - | - | - |
| 50 | 6.09 | 6.02 | disabled | |
| 100 | 5.63 | 5.57 | disabled | Preview (always labelled `PreviewN100`) |
| 150 | 5.49 | 5.43 | disabled | |
| 300 | 5.35 | 5.31 | disabled | |
| 500 | 5.30 | 5.26 | disabled | |
| 900 | 5.27 | 5.22 | allowed | first N where the convention is allowed |
| 1000 | 5.27 | 5.22 | allowed | reference N of the convention |

Every map also shows the **percentage of in-mask voxels above the rule**: the |T| ≥ 7 convention passes about 64% of
the voxels of a map of a random lesion at N = 1000, so a large share of voxels can pass a threshold that looks strict.

**Global signal regression.** The connectome's metadata says whether its preprocessing included global signal
regression (GSR). Without GSR, a symmetric |T| rule shows a banner ("Non-GSR connectomes centre uninformative
connections above 0; consider asymmetric or effect-size thresholds (Cohen & Fox 2021)"). With GSR, negative peaks are
annotated that the size of negative correlations is influenced by GSR (Murphy & Fox 2017).

**The primary threshold is fixed** by the recipe or the locked plan. Other thresholds are sensitivity checks (see
[Robustness](#robustness)); there is no selection of the threshold that looks best. Moving the threshold changes only
the transparency of the colour table, so it is instant.

## Sensitivity: overlap

The classic cohort result is the **overlap** of the lesions' thresholded maps: at each voxel, the number (or percent) of
lesions whose map passes the rule, and the **sensitivity map**, the voxels reached by at least k % of the lesions
(default 90 %). They are descriptive and are labelled so. An overlap map does not show that a network is specific to a
symptom: lesions anywhere give maps that share the connectome's degree pattern, which inflates the overlap (see
[Null models](#null-models)).

## Specificity: the general linear model

Cases are compared with controls, or a continuous score is related to the maps, with a voxelwise linear model and
**permutation inference** (the Freedman–Lane scheme of Winkler et al., 2014; `glm.py`).

- **Inference.** 5000 permutations by default; the enumeration is exhaustive when the number of distinct permutations
  is at most the number requested, with two subjects of identical design rows counted as one arrangement (as in PALM).
  The family-wise error corrected p value (maximum statistic over voxels) is the primary result,
  p = (1 + #{max null ≥ observed}) / (K + 1), and the false discovery rate (Benjamini–Hochberg) is secondary. The
  smallest p that the number of permutations allows (1 / (K + 1)) and the number of voxels that must reach it before the
  false discovery rate can reach 0.05 are stated.
- **Statistics.** t for a one-row contrast, F for several rows, and the Aspin–Welch v statistic for two groups when
  variance groups are chosen. The permutations run in float32, or in float64 for an exhaustive enumeration and for data
  with a very strong effect.
- **TFCE** (threshold-free cluster enhancement, H = 2, E = 0.5, 26-connectivity) is an option; its FWE p comes from the
  maximum TFCE of each permutation. There is **no cluster-extent inference**.
- **Outputs** (exact header of the connectome mask, names as in [Outputs](lesionnetworkmapping.md#outputs)):
  `…Tstat` or `…Fstat`, `…PUnc`, `…PFwe`, `…PFdr`, `…TfcePFwe`, and `…HedgesG`, `…PartialR` or `…PartialEtaSq`, plus
  `glm.json`, `design.json` and `design_matrix.tsv`. P maps hold plain p (not −log10), 1 outside the mask.

### Design types and checks

A design (`design.json`, format `slicer-lnm-design`) is built from the study's typed columns (see
[Columns and roles](lnm_intake.md#columns-and-roles)); a score, a group, a covariate or a block is always a declared
role, never "every numeric column".

| Design type | What it tests | Permutation scheme |
| ----------- | ------------- | ------------------ |
| `within_cohort` | every block (dataset) holds both groups: symptom-anchored case versus control | labels permuted **within blocks** |
| `cases_vs_control_database` | the cases against a control-lesion database (linked control sets) | free exchange. Confounds that the model cannot adjust for (a group nested in the dataset) are listed under Limitations and in the methods; a dataset covariate collinear with the group blocks the design with an explanation |
| `continuous` | a score related to the maps (symptom mapping) | scores permuted, within blocks when blocks are used |
| `one_sample` | the mean map differs from zero | sign flipping; **always warned**, because lesion network maps are never centred on 0 |

- **Lesion volume is a covariate and is on by default.** Turning it off asks for a short reason, which is recorded.
- **Coding.** An intercept plus treatment dummies (the reference level is the last level), or cell means for F contrasts.
  Numeric covariates are mean-centred after an optional log or z transform.
- **Listwise exclusion.** Rows without the covariates or the score are left out and the count is shown. Missing values
  are never imputed.
- **Checks before the run.** The design is blocked or flagged for a rank-deficient design, no intercept, a contrast that
  is not estimable, maps from different connectomes or subject lists, non-finite values, fewer than 100 distinct
  permutations, a variance inflation factor above 5, fewer than 10 per group and a variance ratio above 4. The same
  checks run on a design that is imported from PALM.
- **Review gate.** When the study requires review, lesions that no reviewer has approved are not analysed, and
  automatic lesions need a human approval whatever the setting (see [Review](lnm_intake.md#review-blinding-and-agreement)).

### A-priori regions of interest

When regions of interest are stated before the analysis (the locked plan, see [Recipes](#recipes-and-the-analysis-plan)),
the module tests the ROI means with the same design and permutations, with the maximum statistic across ROIs as the
correction, or restricts the voxelwise test to one ROI mask (small-volume correction). ROI masks must be on the
connectome grid.

### Legacy two-group maps

The Welch t of the mean Fz maps and the Liebermeister statistic of the binarised maps are available, labelled "legacy
two-group, no covariates".

## Symptom mapping (sLNM)

The partial correlation of each voxel with a continuous score, with lesion volume as the default covariate
(`slnm.py`; Siddiqi et al., 2021; Petersen et al., 2026).

- **Inference** is the same Freedman–Lane permutation test as above, with the score as the effect of interest. The
  effect size is the partial r = t / √(t² + df). The parametric p value of a correlation is never used.
- **Spearman** ranks the score, the numeric covariates and, voxel by voxel, the maps, so that the partial r is a partial
  Spearman correlation. **Flip** multiplies the score by −1 (for example for TMS cohorts, where a larger
  anticorrelation means a better response); it is recorded.
- **Leave-one-dataset-out (LODO).** With at least two datasets of at least 10 subjects each, the module computes a
  partial-r map per dataset, their (n − 3)-weighted Fisher-z combination, the cross-dataset spatial r and the
  leave-one-dataset-out r, with p values from block permutations (the scores are shuffled within each dataset).
  Convergence is descriptive: a Stouffer z and an I² heterogeneity map.
- **Control scores.** The same pipeline can be run for control score columns and compared with the main map by spatial
  r, with a permutation p computed from the raw inputs, and by the partial spatial r given the reference maps μC_r and
  PC1 ("r = 0.56 → partial (PC1, μC) r = 0.30, p_perm = 0.11").

## Voxel-based lesion-symptom mapping (VLSM)

The Cohort card's VLSM tab runs the lesion–symptom test on the cohort's own **binary lesion masks** (`vlsm.py`), so it
needs a study but no connectome. The lesion masks are loaded onto the 2 mm template grid of the study's family and
binarized at an occupancy of 0.5.

- A voxel is tested if at least max(5, ⌈10 % of n⌉) lesions cover it (the minimum overlap, shown as "≥ k of n lesions");
  voxels lesioned in every lesion have no variance and are dropped and counted.
- Lesion volume is a covariate by default (the same rule as above); the test is the same permutation GLM, with the
  binary lesion values as the outcome. The t equals the classic VLSM t of `score ~ lesion + volume`.
- Outputs are in `derivatives/lnm/vlsm/<contrast>/`: the maps (`…desc-vlsm<Contrast>…`), the coverage map and the tested
  mask, `lesions.tsv` (no paths), `vlsm.json` with an FWE cluster table, and the design.
- **Seed from VLSM cluster** maps a significant cluster as a circuit (the Circuits card); the run id of the VLSM and
  the lesions are recorded as the circuit's parents.

## Null models

The classic overlap is hub-inflated (Cui et al., 2026). The Nulls card puts it next to a null-referenced version that
is computed from **null cohorts**, sets of lesions that keep some property of the observed cohort but not its
locations (`nulls.py`).

| Kind | Null cohort | Tag in the outputs |
| ---- | ----------- | ------------------ |
| Independent relocation | each lesion rigidly relocated, independently: keeps every lesion's shape and weights, destroys the overlap | established (Zalesky & Cash, 2026; van den Heuvel et al., 2026) |
| Cohort shift | one shared shift of the whole cohort: keeps the shapes and the pairwise Dice exactly | proposal of this project |
| Strength-matched | each centroid moved to one of the 100 brain voxels whose signed μC_r (or hubness) is nearest the lesion's own | 2026 (Zalesky & Cash) |
| Overlap-matched | simulated annealing of the centroids so that the pairwise-Dice histogram matches the observed one | single preprint (Cui et al., 2026); experimental; fast mode only |
| Empirical pool | for each lesion a volume-matched lesion of a control set, with cached exact maps | established practice |

Two modes, always named in every output:

- **Exact** ("pooled exact null, K_pool per lesion"): relocations are mapped exactly, at every connectome voxel, as extra
  seed columns of the same engine passes (default 20 relocations per lesion and 1000 null cohorts).
- **Fast** ("approximate"): relocations and observed lesions are mapped with the fast parcel index (K up to 10,000). Only
  top-x % rules apply, the observed map is recomputed in fast mode, and the parity gate of the index decides which
  lesions take part. **Fast-mode maps are never reported as final observed maps.**

Per voxel, with O the observed overlap count and O_b that of null cohort b: the excess over the null in percentage
points of the lesions (`sensNullExcess`), the one-sided p = (1 + #{O_b ≥ O}) / (K + 1) with Benjamini–Hochberg q, the
FWE p of the maximum standardised excess, and the **bias map** (the share of null cohorts that pass the classic rule).
The caption states the false-positive rate of the classic rule, for example "≥90% at the rule: 31% of brain voxels
pass; random sets: 28% (5–95%: 22–35%)". A cohort's QA chip is calibrated against null cohorts.

## The reference specification (`lnm-reference-v1`)

The reference maps describe what every network map of a connectome shares, whatever the lesion. They are computed once
per connectome and subject list under one versioned definition and are used by the QA chips, the nulls, validation,
the fast index and the methods text (`reference.py`).

| Map | Definition |
| --- | ---------- |
| `mu_r` (μC_r) | for each voxel, the mean over subjects of the mean over runs of its mean r to every other voxel; exact |
| `mu_z` | the mean over K sampled seed voxels of the mean over subjects of the Fisher z of r; sampled |
| `sigma_r` | the standard deviation over the K sampled seeds of the group-mean r; sampled |
| `hub_abs_z` (hubness) | the connectome's mean \|Fz\| to its seeds (the stored degree map, else computed from the same seeds); sampled |
| `pcs` (PC1–PC3) | the leading spatial modes of the column-centred group correlation matrix (randomized block subspace iteration, matrix-free; signs fixed so that each correlates positively with μC_r) |
| `ev1` | optional: the leading eigenvector of the uncentred matrix |

The maps are written to `derived/reference/` of the connectome (or to a subfolder named by the hash of another subject
list). Building them takes about 15 to 25 minutes on a full-size connectome and starts only after you confirm. The
convergence of the randomized components is kept in `reference.json`.

## Connectome-confound QA

Each map is compared with the reference maps: r and Spearman ρ with μC_r, PC1–PC3 and hubness, and R² on the four
together. The **relocated-lesion null** (50 relocations per lesion for a single lesion, fewer as a cohort grows) turns the
similarity into a calibrated chip: below the 5th percentile "less degree-like than relocated lesions", between the 5th
and 95th (amber) "indistinguishable from relocated lesions on this axis", above the 95th (red) "more degree-like".
The **debiased view** shows the map with μC_r and PC1 regressed out; it is descriptive, "not an inferential correction".
See [QA](lesionnetworkmapping.md#qa).

## Validation against baselines

A circuit is only evidence if it predicts held-out patients better than simple alternatives. **Validate**
(`validate.py`) tests a circuit out of sample against mandatory baselines.

- **Folds.** Leave-one-dataset-out when every held-out dataset holds both classes (or at least 10 subjects for a score);
  otherwise stratified 10-fold × 5 repeats, with the reason. Leave-one-out is allowed with a warning.
- **In-fold circuits** are built from the training subjects only: the unthresholded GLM t map, the sLNM partial r map or
  the top-x % ROI. No permutation-FWE threshold is applied inside a fold. A held-out lesion never enters its own
  circuit (an assertion checks it). Training subjects are scored with an inner cross-fit so that the score is not
  inflated.
- **Models and baselines**, always computed in the same folds: lesion volume only; volume plus the μC_r score; volume
  plus the PC1 score; volume plus the in-fold lesion-location map; optional reference maps. A baseline that cannot be
  computed is reported with the reason.
- **Metrics.** AUC and the odds ratio per SD for a binary outcome; r and the out-of-sample R² for a continuous one,
  with whole-procedure bootstrap intervals (200 resamples) and a permutation p (1000 permutations of the outcome within
  datasets, with the whole pipeline rerun).
- **The verdict text is neutral**, for example "does not exceed the degree baseline (ΔAUC 0.01, 95% CI −0.04 to 0.06)".
- **Frozen circuits.** A circuit fixed by another study (a file and its sha256) can be scored on a new cohort, with
  metrics and a simple bootstrap interval and no fitting.

### Damage scores and the circularity guard

The Circuits card scores each lesion's damage to a circuit (the sum of the circuit over the lesion, the occupancy-weighted
mean, the percentage of the lesion inside the thresholded circuit; optionally residualised on lesion volume). Every
result carries a provenance: `frozen` (the circuit was made from other lesions, or declared frozen with its sha256) or
`same_cohort`. **A same-cohort circuit cannot be tested against an outcome** (selecting a circuit on a cohort and testing it
on the same lesions is circular): use Validate or a circuit frozen from an independent cohort. User-given stimulation
targets are scored against random spheres in gray matter (research only); the module never proposes a coordinate.

## Robustness

Robustness analyses are secondary: they never replace the primary map and never select a best setting
(`robustness.py`).

- **Threshold sweep.** The existing per-lesion maps are re-thresholded over published alternatives: FWE; |T| ≥ 5, 7, 9, 12
  (only for N ≥ 900); the top 5, 10 and 25 % of |map|; and overlap of at least 50, 75, 90, 95 and 100 % of the lesions.
  For each setting the result states the voxels, the Dice and r against the primary, and whether the primary peak
  persists within 10 mm. The first setting where the conclusion changes is reported as "conclusion flips at …".
- **Replication on another connectome.** The same lesions are mapped on a second connectome; maps are compared by
  unthresholded spatial r, by Dice at the rule **re-resolved for that connectome's own N and V**, and by the persistence
  of the top three peaks within 10 mm. r below 0.7 is flagged next to published reference values. Cross-connectome r
  measures how much the conclusion depends on the connectome; it is not sampling noise.
- **Lesion split-half** (Ferguson et al., 2019). The lesions are split at random into halves, many times (seeded);
  each split gives the spatial r of the two overlap maps, the Dice of the sensitivity maps and, with a design, the r of
  the t maps.
- **Leave-one-lesion-out influence** (a downdate, not a refit): the sensitivity map's Dice against the full map, the
  change of the GLM peak, and the most influential lesions.
- **Seed variants** and **hemisphere consolidation** write derived lesion files to the run folder (never to `lesions/`).
  Mirroring is approximate; consolidation is a recorded analysis option, never automatic.
- **Connectome split-half** (odd and even subjects of one connectome) is reported with the connectome results and labelled
  as such, never next to the lesion split-half.

## Calibration

**Calibrate this analysis** (`calibrate.py`) catches design and coding errors on your own lesions before publication.

- **Empirical FWER.** K null datasets of the configured design (default 100) run the full pipeline; a null dataset counts
  as an error when any voxel reaches FWE p ≤ α. The rate is shown with an exact binomial (Clopper–Pearson) interval and
  is "inflated" (amber) when the lower bound exceeds α. A one-sample design has no labels to permute, so its null
  datasets are random sets of lesions of the same size (which is why one-sample designs are warned).
- **Sensitivity false positives.** Random or relocated lesion sets are put through the classic overlap rule, the
  null-referenced FWE and their conjunction.
- **Planted-network recovery.** A simulated score is planted on the lesions' connectivity to a target network at several
  effect sizes (default 0.1, 0.2 and 0.3); the result is power, the distance of the peak to the target and the spatial r
  with the truth, also after partialling μC_r and PC1.

One null dataset of 500 permutations took about 4.3 s at n = 200 and V = 228,483 on the development computer; the card
shows an estimate before it starts.

## Recipes and the analysis plan

A **recipe** is a named, cited and fully visible set of choices (primary rule, overlap level, statistic, design defaults,
nulls, permutations, validation scheme, robustness set and the ordered steps). No recipe is labelled "recommended". A
recipe adapted from a publication lists every difference from it. The built-in recipes are `quicklook_boes2015`,
`preview`, `classic_ferguson2019_adapted`, `darby2019_cnm`, `siddiqi2021_slnm`, `petersen2026_label_permutation`,
`vdh2026_standard_settings` and `comprehensive_battery`; a lab can add its own (the `Studio/LNM/RecipeFolders` setting,
or a study's `recipes` folder). A step that is not available in a build is shown as "not available in this build".

**Lock analysis plan…** writes `derivatives/lnm/analysis_plan.json` (the recipe, the parameters, the hypotheses with the
sha256 of any a-priori ROI) and its own sha256. After the lock, every change of a parameter is appended with its reason to
`analysis_plan_deviations.jsonl`, which the methods text reports. This includes the permutations, covariates, input, FDR
and TFCE of the Cohort card's Contrast tab and the permutations and covariates of its Symptom tab: a change there is shown
in the Recipe header ("Contrast GLM: n_perm 1000 instead of 5000"), and that tab's Run waits until the reason is recorded
or **Use the plan's settings** sets the tab back. These changes apply to that analysis only, not to Run everything.

## Reporting checklist

The Report card evaluates 15 items (A1–K15) from what was run and written, each "done", "not run", "N/A" or "flagged"
(lesion source, lesion-set properties, control set, connectome identity, seed and statistic, thresholds and robustness,
overlap and null, design and correction, μC/PC1 with null and partial, cross-condition repetition, out-of-sample
validation, replication, second connectome and split-half, sharing, interpretation wording). The battery strip shows
six dots (degree and PC1 QA, null reference, specificity, validation, robustness, provenance and sharing): grey for not
run, green for run, amber for run and flagged. **Checklist warnings never block an export**; only hard errors do (an
invalid design, non-finite maps, mixed connectome hashes, failed post-run assertions).

## What is deliberately not offered

- An automatic "specific" verdict, a "best threshold" or a "best connectome".
- A neuromodulation target finder: only user-given targets are scored, against random sites.
- Cluster-extent inference with arbitrary cluster-forming thresholds.
- A spin-test or BrainSMASH p value for volumetric maps. The permutation p values that compare two maps
  (Compare card) come only from raw in-study inputs (scores or labels permuted), and a pair that has no such inputs shows
  no p, with the reason.
- Reporting fast-mode maps as observed results.
- A live network preview while tracing or reviewing, automatic lesion extraction from figures or text, and nonlinear
  warping of figures.
- Silent imputation, silent resampling or silent reuse of an N-dependent threshold.
- An automatic flip of all lesions to one hemisphere (hemisphere consolidation is an explicit, recorded option).

PALM and FSL randomise are never bundled or run: **Export for PALM…** writes the design, the contrasts, the exchangeability
blocks and a `run_palm.sh` that reproduces the in-app design (and the same matrices in FSL VEST format), and PALM's
results can be imported again.
